# Launch kit

Drafts for you to post. **Post them yourself** — automated posting gets accounts
banned on every platform here, and the drafts need your voice anyway.

## What actually moves a repo

Ranked by what reliably works for developer tools:

1. **Show HN**, posted Tue–Thu around 09:00 ET. The single highest-leverage
   post. Front page for a few hours moves more stars than months of everything
   else combined.
2. **A specific subreddit**, not r/programming. r/LocalLLaMA, r/SaaS,
   r/ExperiencedDevs. Read each one's self-promotion rule first — several will
   remove a link post from a new account.
3. **A written post with a real number in it.** "What it cost to run a
   14-agent company for a week: $43.18, itemised by role" will outperform any
   announcement, because the ledger is the part nobody else publishes.
4. **Answering issues fast in week one.** The first ten issues decide whether
   anyone comes back.

## What does not work

- Buying or botting stars. It violates GitHub's Terms of Service, it is
  detectable from the join-date and activity distribution of the accounts, and
  the outcome is a delisted repository. There is no version of this that ends
  well.
- Follow-for-follow and star-for-star rings. Same outcome, slower.
- Posting the same text to twenty subreddits. Reads as spam and gets your
  domain filtered site-wide.

## Honest expectations

Roughly 40 repositories in GitHub's entire history have passed 100k stars, and
they are things like Linux, VS Code, and React. A genuinely useful developer
tool with a good Show HN run typically lands **200–2,000 stars in its first
month**. Anything beyond that comes from sustained usefulness over years, not
from a launch.

The thing most likely to actually earn attention here is the cost ledger —
publish real spend numbers as you run it. That is the part of this problem
everyone else hand-waves.
